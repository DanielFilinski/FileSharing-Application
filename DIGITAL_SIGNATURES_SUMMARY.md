#### **1. Типы и интерфейсы**
- 📁 `src/shared/types/signature.ts` - Полный набор типов:

#### **2. Основной сервис**
- 📁 `api/src/shared/signature/signatureService.ts` - `SignatureService`:
  - ✅ Создание и управление запросами на подпись
  - ✅ Обновление статусов подписантов
  - ✅ Работа с настройками организации

  - ✅ Интеграция с CosmosDB

#### **3. API Endpoints**
- 📁 `api/src/functions/digitalSignature.ts` - Полный набор endpoints:
  - `POST /api/documents/{id}/sign` - Создание запроса на подпись
  - `GET /api/signature-requests` - Получение запросов пользователя
  - `GET /api/signature-requests/{id}` - Детали конкретного запроса
  - `PUT /api/signature-requests/{id}` - Обновление запроса
  - `DELETE /api/signature-requests/{id}` - Отмена запроса
  - `POST /api/signature-requests/{id}/signers/{email}/status` - Webhook для обновления статуса подписанта
  - `GET/PUT /api/signature-settings` - Настройки организации
  - `GET/POST /api/signature-templates` - Управление шаблонами
  - `GET /api/signature-statistics` - Статистика
  - `POST /api/signature-webhooks/{provider}` - Webhook endpoints для внешних провайдеров

#### **4. База данных**

## 🏗️ Архитектурные решения

### **1. Гибридный подход к провайдерам**
- Подготовлена интеграция с DocuSign и Adobe Sign
- Возможность собственной реализации для простых случаев
- Webhook endpoints для получения обновлений от внешних провайдеров

### **2. Роли и права доступа**
Согласно `PROGECT.md`:
- **Administrators/Technical Support**: Полный доступ к настройкам подписи
- **Service Providers**: Настройка методов подписи для организации
- **Regular Employees**: Доступ к инструментам подписания документов
- **Clients (End Users)**: Возможность подписывать документы при необходимости

### **3. Методы подписи**
Реализована поддержка:
- **E-Signature**: Цифровые подписи с верификацией через email
- **Digital Certificate**: Подписи с использованием сертификационных центров
- **Drawn Signature**: Рукописные подписи с timestamp верификацией
- **Internal**: Внутренняя система подписи

### **4. Настройки безопасности**
- Multi-factor authentication
- Session timeout для процесса подписания
- IP ограничения для доступа к подписанию
- Полный audit trail всех операций

## 📊 Workflow и процессы

### **1. Создание запроса на подпись**
1. Пользователь выбирает документ → "Sign Document"
2. Открывается SignatureWidget с настройками
3. Добавление подписантов (email, роль, порядок)
4. Настройка параметров (сроки, уведомления, метод)
5. Создание запроса через API
6. Уведомления подписантам

### **2. Процесс подписания**
1. Определение требований к подписи
2. Назначение подписантов и уведомления
3. Последовательное или параллельное подписание
4. Обновление статусов через webhooks
5. Завершение процесса и уведомления

### **3. Отслеживание статуса**
- Колонка "Signature" в таблице документов
- Компактное отображение прогресса (X/Y подписано)
- Детальный просмотр с информацией о каждом подписанте
- Обновление в реальном времени
